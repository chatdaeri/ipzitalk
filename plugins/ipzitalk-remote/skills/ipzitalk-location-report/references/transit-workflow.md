# 교통 환경 워크플로우 (공유 부품)

> 이 파일이 정본이다. 스킬 폴더 밖 경로에 의존하지 않는다(standalone).
> 이 보고서의 교통 축 전용 워크플로우다. center 좌표를 공유한다.
> **최종 갱신 2026-07-09** — 반경 규칙 R1~R3 · 45건 캡 · 더블/트리플 라벨 · 지도 규칙 반영.

## 반경 처리 (R1~R3) — `radius_m`은 판정이 아니라 관측 파라미터다
| 층위 | 값 | 사용자 `radius_m` |
|---|---|---|
| **밴드**(등급 판정) | 축별 절대 거리, 불변 | 영향 없음 |
| **표시 반경**(지도 원·목록) | 기본 1,500 | 그대로 반영 |
| **수집 반경**(API 호출) | `max(radius_m, 밴드최대 1200 × 1.25)` | 하한만 보장 |

- **R1.** 밴드는 절대 기준. 반경을 넓혀도 좁혀도 등급은 안 움직인다.
- **R2.** 수집 반경은 항상 밴드 최대 이상으로 자동 확장. 안 그러면 "반경 내 없음"과 "이격"을 구분 못 한다.
- **R3.** 요청 반경 밖이라도 최근접 1건은 회색 + "요청 반경 밖" 꼬리표로 표시한다.
- **cap 5,000m.** 2,000m 초과 시 45건 캡 경고 강제 표기.
- **광역 축 격리**: 철도(12km)·버스터미널(15km)은 `radius_m` **미적용**. 1km를 줬다고 터미널을 1km에서 찾으면 3km 고속터미널을 놓쳐 "미흡"으로 오판한다.

## 검색 단계 (center = 사업지 좌표)
1. **지하철**(근린) — `search_by_nearby_category(center, radius_m=max(radius_m,1500), categories=['subway'])`
   → 노선·역명·직선거리. 카테고리 조회라 잡음 없음.
2. **철도**(광역, 고정 12,000m) — `search_by_nearby_keyword(center, radius_m=12000, query="기차역")`
   → **`폐역` 제외**(name/category_name에 "폐역" 포함 시 드롭). KTX정차역 표기 유지.
3. **버스터미널**(광역, 고정 15,000m) — `search_by_nearby_keyword(center, radius_m=15000, query="버스터미널", category_filter={include_contains:["터미널"]})`
   → **ATM·비터미널 노이즈 제거**.

## 🚨 45건 캡
`search_by_nearby_category`는 쿼리당 45건 상한이고 **`grid` 옵션이 없다**(키워드 검색에만 있다).
다만 `sort=distance`라 **최근접은 항상 정확** → **등급 판정은 안전, 목록·개수는 근사.**
해당 카테고리의 `pagination_by_category.source_cap_reached=true`이면 "목록 불완전" 경고를 단다.

## 0건이 나오면 재확인한다 (🚨 부재 단정 금지)
카테고리 검색의 45건 캡은 **서버가 아니라 후처리 필터**라, 밀집지역에서는 실제로 있는 시설이 0건으로 보일 수 있다.
0건이 나온 축은 ① 해당 카테고리의 `pagination_by_category.source_cap_reached` 확인 → ② 같은 축을 `search_by_nearby_keyword` 로 한 번 더 조회(반경 동일, center 재해소 금지) → ③ 카테고리 cap 미도달이고 keyword 첫 페이지도 0건이면 **"반경 내 없음"** 확정, 한쪽이라도 cap에 걸리거나 결과가 엇갈리면 **"확인 불가(검색 한계)"** 로 적는다. 최근접 판정에는 keyword 추가 페이지를 호출하지 않는다.

## 밴드 (직선거리)
| 항목 | 우수 | 양호 | 보통 | 미흡 | 축 |
|---|---|---|---|---|---|
| 지하철 | ≤500m | 500–800 | 800–1200 | >1200 | 근린 |
| 철도(기차/KTX) | ≤2km | 2–5km | – | >5km | 광역(고정) |
| 버스터미널 | ≤3km | 3–7km | – | >7km | 광역(고정) |

## 더블 · 트리플 역세권 라벨 (지하철 축만)
**판정창 1,000m 안에서 이용 가능한 서로 다른 지하철 노선 수**로 라벨을 붙인다.

| 1km 내 노선 수 | 라벨 |
|---|---|
| 1 | 역세권 |
| 2 | 더블 역세권 |
| 3 | 트리플 역세권 |
| 4+ | 쿼드러플 역세권 |

- **세는 단위는 노선이다.** 역 개수도, 카카오 레코드 수도 아니다.
  - 환승역은 노선별로 쪼개져 온다(`사당역 4호선` / `사당역 2호선` = 레코드 2, 역 1, 노선 2).
  - 역명이 달라도 같은 역사인 경우가 있다(`이수역`=7호선 / `총신대입구역`=4호선). **역명 dedupe로는 못 걸러진다.**
  - 노선 추출: `kakao_category_name` 말단 세그먼트(`… > 수도권7호선`).
- **등급은 올리지 않는다.** 라벨은 pill·한줄평에만.
- 개통예정 노선(GTX 등)은 세지 않는다 → 수기 편집 영역.

## 종합 등급 (★ 3단계)
- **지하철 주 가중**, 철도·터미널 보조.
- 지하철 최근접 ≤500m → ★★★ / 500–1200m → ★★☆ / >1200m → ★☆☆.
- **지하철 0건**(지방·철도중심): 철도(≤2km 우수 / 2–5km 양호 / >5km 미흡)·터미널로 대체 판정. 한줄평에 "지하철 없음 · 철도/버스 기준" 명시.
- **도심 입지 보정**: 철도 원거리(>5km)여도 지하철 도보권(≤500m)이면 ★★★ 유지 가능.
- 더블/트리플 라벨은 등급에 반영하지 않는다.

## 지도 호출 규칙 (서버 렌더 버그 회피)
- `get_map_embed_url`에 `center` + `radius_m`을 **항상 함께**, 마커는 **2개 이상**(1개면 서버가 `zoom:15` 고정).
- 🚨 **반경 눈금 마커를 넣지 않는다.** 예전엔 `fitBounds`가 반경 원을 무시해 원이 잘리는 걸 막으려고
  정북·남·동·서에 회색 더미 마커 4개를 심었다. 사용자에게는 **정체를 알 수 없는 점**으로 보여 혼란만 준다.
  **원이 잘리더라도 마커는 실제 장소만 찍는다.** (근본 해결은 `render.ts`가 원을 bounds에 포함하도록 고치는 것 — 발견사항 6번)
  `dLat = r×1.05/111320`, `dLng = r×1.05/(111320×cos(lat))`. 없으면 원이 잘린다(방배 실측 10/10 발생).
- 역 마커 노선색: 2호선 `#00A84D` · 4호선 `#00A5DE` · 7호선 `#747F00` · 판정창 밖 `#94a3b8`.
- 카드 CSS: `.map{overflow-x:auto}` + `.map iframe{min-width:720px}` (좁은 화면 최소줌 방지).

## hedge (필수 승계)
- 직선거리 기준 · 실제 도보/차량 소요시간·배차·환승 미반영 · 폐역·비터미널 필터 결과 · 출처(카카오 로컬)·조회일.
- 금지: "도보 N분 확정", "개통 확정"(호재는 수기·출처 필수), 근거 없는 우열 단정.

## 엣지
- 지오코딩 실패/`NOT_FOUND` → 재입력 · 후보 다수/`AMBIGUOUS` → 후보 나열.
- 지하철/철도/터미널 0건 → "없음/원거리" 명시, 거리 지어내지 않음.

- 1km 판정창 노선 = {7, 4, 2} → **트리플 역세권**. 판정창을 1.2km로 넓혀도 노선 집합 불변.
- 철도: 용산역 KTX 5.4km(미흡) · 영등포 7.6km · 서울역 7.9km.
- 터미널: 남부터미널 2.8km(우수) · 센트럴시티 3.0km · 고속터미널 3.3km.
- 종합 **★★★ 우수** (도심 입지 보정 적용).

## 🚨 개통 예정 역이 장소명에 섞인다 (실측 2026-07-09)

카카오는 개통 예정 역을 **장소명 문자열**로 표기하고, 카테고리도 지하철로 준다.

```
"위례호수공원역 (2026년12월예정)"   215m   category_name: 교통,수송 > 지하철,전철
```

**다행히 `search_by_nearby_category(categories=['subway'])` 는 이것을 반환하지 않는다.** 실측:
```
반경 500m · categories:['subway']  → 0건        (215m 예정역이 있는데도)
반경 1000m · query="공원"(키워드)   → 예정역이 나옴
```

- 🚨 **지하철은 반드시 카테고리 검색을 쓴다.** 키워드 검색으로 바꾸면 미개통 역이 최근접이 되어 등급이 통째로 뒤집힌다.
- 키워드 검색을 쓰는 축(철도 `query="기차역"`, 터미널 `query="버스터미널"`)은 장소명에
  `예정`·`개통`·`(20NN년` 이 포함되면 **판정에서 제외**하고 목록에만 꼬리표를 단다. **연도를 지어내지 말 것.**
- 학교도 같은 함정이다(`"산빛초등학교 (2027년 3월 예정)"`). 운영 중인 시설로만 판정한다.
